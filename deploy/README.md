## Устройство

- `source/`: ссылка на `releases/ux-polish-20260920-r9`, исходники и Dockerfile текущей версии.
- `deploy/`: этот Compose-файл и эксплуатационные скрипты.
- `env/runtime.env`: параметры приложения, токен Telegram, ключи подписи, runtime DSN.
- `env/database.env`: начальная конфигурация PostgreSQL.
- `env/migration.env`: DSN владельца схемы и пароли ограниченных ролей для миграций.
- `backups/`: локальные снимки; автоматически на другой сервер не копируются.

Файлы `env/*.env` имеют права `0600`, каталоги `/opt/fintracker` и `env` — `0700`.
Реальные секреты владельца PostgreSQL не передаются API, worker, scheduler или polling.
Роли `fintracker_api` и `fintracker_worker` не имеют SUPERUSER/BYPASSRLS.

Сервисы: PostgreSQL 17, API, worker, scheduler и один получатель Telegram long polling.
Домен и HTTPS для этого режима не нужны. Входящие обновления сохраняются в ту же
долговечную очередь, которая используется webhook. Одновременно запускать другой
polling-процесс или включать webhook для этого токена нельзя.

API доступен только на `127.0.0.1:18080`, PostgreSQL — только внутри Docker-сети.
Постоянные тома: `fintracker_pgdata`, `fintracker_objects`, `fintracker_securitylog`.
Сервисы имеют `restart: unless-stopped`, ограничения памяти и ротацию журналов.
Существующий VPN-контейнер `amnezia-awg2` в этот проект не входит.

## Управление на сервере

```bash
cd /opt/fintracker/deploy
docker compose -f compose.production.yml ps
curl -fsS http://127.0.0.1:18080/health/ready
docker compose -f compose.production.yml logs --tail=50 worker scheduler polling
```

После редактирования `env/runtime.env` пересоздать процессы, чтобы они получили новые значения:

```bash
docker compose -f compose.production.yml --profile app --profile polling up -d --wait
```

Не публикуйте вывод `docker compose config` или `docker inspect`: в них могут быть секреты.
Для проверки синтаксиса используйте `docker compose -f compose.production.yml config --quiet`.

## Первоначальная установка

Сначала перенести исходники в `source/`, эти файлы в `deploy/`, затем:

```bash
python3 prepare_env.py
# Заполнить env/runtime.env: токен, bot_id и режим создания бюджетов.
docker compose -f compose.production.yml config --quiet
docker compose -f compose.production.yml up -d postgres
docker compose -f compose.production.yml build migrate
docker compose -f compose.production.yml run --rm -T migrate
docker compose -f compose.production.yml run --rm --no-deps -T --entrypoint python api -c \
  'import asyncio; from fintracker.config import get_settings; from fintracker.bot.dispatcher import register_commands; asyncio.run(register_commands(get_settings()))'
docker compose -f compose.production.yml --profile app --profile polling up -d --wait
```

`prepare_env.py` создаёт случайные независимые секреты и отказывается перезаписывать
существующую конфигурацию. `migrate.py` создаёт ограниченные роли и применяет миграции
из установленного пакета. Перед обновлением существующей базы сделайте снимок.
Повторный запуск миграций не означает, что downgrade старого образа совместим с новой схемой.

## Telegram и AI

`FINTRACKER_TELEGRAM__BOT_ID` должен совпадать с ID из `getMe`.
При `CREATION_MODE=allowlist` перечислите Telegram user ID через запятую в
`FINTRACKER_TELEGRAM__CREATION_ALLOWLIST`; при `open` бюджеты может создавать любой пользователь.

До предоставления ключа OpenAI `FINTRACKER_AI__ENABLED=false`: доступен ручной ввод,
а AI-анализ/распознавание не подключены. Чтобы включить AI, сначала проверить доступ
ключа к модели `gpt-5.6-luna` с effort `medium`, затем заполнить
`FINTRACKER_AI__API_KEY` и изменить `FINTRACKER_AI__ENABLED=true`.
Голос требует отдельной настройки ASR; один ключ сам по себе ASR не включает.

## Снимок перед обновлением

```bash
bash /opt/fintracker/deploy/backup.sh
```

Скрипт ненадолго останавливает работающие сервисы только этого проекта, делает
`pg_dump`, архив вложений/журнала доступа и копию конфигурации, проверяет читаемость
архивов, затем запускает ранее работавшие процессы. Незавершённые снимки имеют
суффикс `.partial`. Снимки содержат секреты и должны оставаться приватными.

Автоматическое расписание, внешнее хранение, WAL/PITR и проверка полного восстановления
этими скриптами не настроены. Локальный снимок не защищает от потери сервера.

Начальный снимок создан и проверен на читаемость:
`/opt/fintracker/backups/20260919T162251Z`. После него все сервисы повторно прошли
проверку готовности. Это проверка архивов и перезапуска, а не учение полного восстановления.
