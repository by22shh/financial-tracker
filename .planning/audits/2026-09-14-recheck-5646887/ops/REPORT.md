## O-01 — P1: допустимый по исходящей схеме null отклоняется собственным парсером

`src/fintracker/infra/ai/schemas.py:270–274` добавляет nullable каждому полю,
которое Pydantic не включил в required, в том числе массивам с default_factory.
Но `ExtractionResponse.candidates` остаётся `list[ExtractionCandidate]` без None.
`openai_client.py:190` передаёт результат прямо в `model_validate_json` без
нормализации этого нового представления.

Проба создала обычный валидный `ExtractionResponse(intent='question')`, включила
все поля через model_dump и заменила только candidates на null. Исходящий JSON Schema
явно допускает `type: ['array', 'null']`; остальные поля сохранены валидными.
Настоящий OpenAIResponsesProvider получил этот ответ через контролируемый HTTP 200.
Обе попытки отвергнуты с `Input should be a valid array`, итог — ValidationFailed.
Это не измерение поведения живой модели: проверена внутренняя несовместимость двух
контрактов на стороне приложения.

**Исправление:** сделать required все поля, сохраняя их исходную допустимость null,
либо ввести отдельные согласованные модели внешнего ответа и нормализацию в доменную
модель. Не предлагать провайдеру значение, которое затем объявляется ошибкой схемы.
Добавить round-trip проверки схем и моделей, включая вложенные коллекции.

**Проба:** `test_strict_response_allowed_null_is_accepted`.

## O-02 — P2: усечённый PNG с заголовком допускается к vision

`src/fintracker/domain/media/image.py:94–98` проверяет только 24 первых байта:
сигнатуру, имя IHDR и размеры. Нет проверки длины/CRC IHDR, наличия IDAT/IEND
или декодируемости пикселей. JPEG аналогично возвращает размеры сразу после SOF.

В реальный `handle_media` подан `png_bytes()[:24]`: пикселей, контрольной суммы и
конца PNG нет. Файл принят, ScriptedAIProvider вызван, показана карточка чека на
450 ₽. Ожидаемое отклонение до provider call не произошло. Штатный G-26 проверяет
обычный текст вместо картинки и потому проходит.

**Исправление:** проверять целостность и декодируемость скачанного изображения
с лимитами ресурсов до AI. Проверки размеров заголовка оставить как ранний предел,
но не считать их доказательством корректного файла.

**Проба:** `test_truncated_png_rejected_before_vision`.

## O-03 — P2: существующий каталог без права записи объявляется writable и ready

`src/fintracker/runtime/health.py:124–132` лишь вызывает конструкторы backend.
Конструктор делает mkdir(exist_ok=True); это успешно для существующего каталога,
даже когда создание файлов запрещено.

Проба создаёт каталог с режимом 0500 под обычным текущим пользователем ОС.
Фактический `storage.put` получает PermissionError. После этого `check_readiness`
возвращает `storage_writable=True`, `ready=True`, `detail=None` при исправной БД.
Новый штатный тест использует недоступного родителя и отсутствующего потомка;
тот частный случай не проверяет существующий read-only mount.

**Исправление:** проверять реальную временную запись/чтение/удаление в namespace
health-проб, включая ошибки файловой системы. Одна проверка режима доступа не
обнаружит read-only mount или исчерпание места.

**Проба:** `test_existing_readonly_root_is_not_ready`.

## O-04 — P1: процессы с документированными параметрами запуска не разделяют хранилище

`Dockerfile:54–55` объявляет VOLUME, но не подключает именованные общие тома.
Примеры `docker run --rm ... api|worker|scheduler` в Dockerfile и FINAL_REPORT
также не задают общие mounts; docker-compose содержит только инфраструктурные сервисы.
У каждого контейнера получается свой анонимный том объектов и свой журнал доступа.

Пересобран свежий образ `fintracker:audit-5646887`. В первом контейнере оба backend
успешно записали синтетический файл. Второй контейнер того же образа с теми же
настройками не видит ни объект, ни запись журнала. Mount inventory первого
контейнера подтверждает анонимные volumes. Проба не выполняет полный запуск бота:
она проверяет фактическое разделение filesystem backend между контейнерами.

**Последствие:** worker не сможет прочитать материал другого процесса, а отдельный
пустой ACL-журнал может вызвать карантин существующих бюджетов. Объявление VOLUME
само по себе также не задаёт повторное подключение данных при замене контейнера;
документированный `--rm` удаляет его анонимные тома.

**Исправление:** добавить проверяемую конфигурацию запуска всех трёх процессов с
именованными общими томами для выбранного filesystem backend; журналу задать
требуемые отдельные права и резервирование. Проверить чтение между процессами и
повторное подключение после замены контейнера.

**Проба:** `probe_container.py`, `container-storage.json`; новый образ собирался
отдельным тегом, чужие контейнеры и данные не затронуты.

## O-05 — P2: новая копия сырой подписи переживает очистку исходного ввода

`application/intelligence/media_pipeline.py:78–86` теперь дублирует исходный текст
в `draft.source_media.caption`; для неоплаченного документа сохраняется также
подробный результат разбора. Миграция `0016_draft_source_media.py` добавила JSONB,
но не изменила `maintenance_expire_drafts`: та очищает только raw_text/transcript
(`0009_runtime_maintenance.py:71–73`).

Проба вызывает настоящий `_prepare_media`, затем выставляет срок очистки и срок
черновика в прошлое. Реальная WORKER-функция `sweep_private_drafts` сообщает об
очистке одной записи. raw_text уже NULL, но исходная подпись полностью сохранена
в source_media.caption. Операция не проведена, отдельная выбранная заметка не
создана. Поэтому исключение для структурированной операции/заметки неприменимо.

**Исправление:** включить новые копии сырого материала в миграцию функции очистки
и в политику повторной обработки. Обработчики повторения должны явно сообщать об
истечении исходного материала. Проверить все копии сырого текста и подробного
разбора по RET-03/RET-08 и таблице сроков ТЗ §24, а не только старую колонку.

**Проба:** `test_media_caption_is_erased_at_raw_data_deadline`, отдельные
`retention/junit.xml`, `retention/pytest.log`, `retention/scope.json` —
1 failed, 0 errors/skipped, 4,65 с. Тест реально проверяет подпись; сохранённый
подробный результат упомянут как второй потребитель той же новой колонки,
а не как отдельное выполненное воспроизведение.
