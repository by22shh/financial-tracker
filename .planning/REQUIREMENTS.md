### SEC — безопасность и приватность (TZ §24, ADR-06/11/14)

| ID | Правило |

| SEC-01 | Личность только из доверенного Telegram Update или серверной сессии |
| SEC-02 | RLS ENABLE+FORCE на таблицах бюджета; runtime роль не владелец, без BYPASSRLS |

### FORM — денежные и календарные формулы (TZ §10–11, §9.1.1)

| ID | Формула / правило |
|---|---|
| FORM-01 | `L[k,p] = лимит + утверждённый перенос`; `S = расходы − возвраты`; `R = L − S`; `C = непокрытая часть обязательств`; `A = R − C` |
| FORM-02 | Процент использования `S/L×100` только при `L>0`; при `L=0` «Расход вне плана»; при `limit=null` «Лимит не задан»; при `L<0` — дефицит переноса без порогов |
| FORM-03 | Прогноз = факт + неисполненные обязательства + прогноз гибких; темп только после ≥7 наблюдаемых дней |
| FORM-04 | Свободные деньги = ликвидные − защищённые − непокрытые обязательства − резерв − буфер (P1) |
| FORM-05 | Взнос в фонд = ⌈недостающая сумма / число взносов⌉, последний взнос корректируется |
| FORM-06 | Календарный повтор: граница = anchor + i×M месяцев, короткий месяц → последний день **этого** месяца, следующая граница снова от anchor |
| FORM-07 | Фиксированный повтор: граница = anchor + i×N календарных дней (не 24×N часов UTC) |
| FORM-08 | Период в базе `[start_date, end_exclusive)`; в интерфейсе обе даты включены |
| FORM-09 | Распределение скидки методом наибольших остатков, сумма частей = итог |
| FORM-10 | Опережение обзора плана `min(3, max(0, длительность_периода − 1))` дней |
| FORM-11 | Ранний риск при превышении `max(500 ₽, 10% лимита)` (настраиваемо) |
