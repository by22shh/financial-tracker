# BLOCKERS — недостающие внешние входы

Формат: что нужно → на какие требования влияет → что уже подготовлено →
какая независимая работа продолжается → условие снятия.

## BL-01 — Ключ OpenAI (OPENAI_API_KEY)

- **Нужно:** серверный ключ OpenAI с доступом к `gpt-5.6-luna` и месячный лимит расходов.
- **Влияет на:** живые проверки AI-01…AI-09, AR-36 (качество), A18–A33 (реальное
  распознавание), A102/A103 частично, раздел 25 ТЗ (корпус качества), NFR-03…05
  (измеренные задержки с реальным провайдером).
- **Подготовлено:** реальный адаптер OpenAI Responses API с профилем ADR-17,
  строгая JSON-схема, валидация, повторы, резервирование стоимости, версионирование
  промптов; контрактные проверки на управляемом HTTP-стабе; деградация на ручной ввод.
- **Независимая работа:** весь детерминированный домен, транспорт, отчёты, импорт/экспорт.
- **Условие снятия:** ключ в переменной окружения/secret manager + подтверждённый
  месячный лимит расходов. До этого живые AI-проверки помечаются `BLOCKED`.

## BL-02 — Выбор модели ASR (OPEN-02)

- **Нужно:** конкретная модель транскрипции (провайдер, id, тариф, условия обработки
  данных) для русского языка.
- **Влияет на:** FR-13, A18–A21, часть AR-36, NFR-04.
- **Подготовлено:** интерфейс `AsrProvider` с контрактом (аудио → transcript +
  сегменты + уверенность + язык), конфигурация профиля, ограничение длительности,
  раздельные таймауты и метрики, детерминированный тестовый провайдер.
- **Варианты для решения:** (a) OpenAI `gpt-4o-transcribe`/`whisper-1` — один
  провайдер и договор с уже выбранным; (b) отдельный специализированный ASR —
  требует второго договора и проверки условий данных.
- **Независимая работа:** весь путь обработки транскрипта тем же профилем Luna.
- **Условие снятия:** выбранная модель + ключ. Реализация адаптера — 1 срез после решения.

## BL-03 — Токен Telegram-бота и публичный HTTPS

- **Нужно:** `TELEGRAM_BOT_TOKEN` тестового бота, домен с TLS для webhook,
  согласованные тестовые участники.
- **Влияет на:** QA-03 (реальные клиенты iOS/Android/Desktop), живая часть A141–A200,
  A66, NFR-02, пилот QA-04.
- **Подготовлено:** полный webhook-контракт с проверкой secret header, долговечный
  inbox, обработчики aiogram 3, очередь доставки с учётом `retry_after`,
  локальный прогон через контролируемый Telegram-стаб и long-polling режим.
- **Условие снятия:** токен + доступный HTTPS endpoint (или разрешение на polling
  в тестовой среде).

## BL-04 — Среда размещения (OPEN-01, OPEN-05)

- **Нужно:** страна использования и размещения, поставщик compute/DB/storage,
  домен, secret manager, канал операционных событий и ответственный.
- **Влияет на:** NFR-09, NFR-10, AR-33 (реальное восстановление на managed PITR),
  раздел 24 ТЗ (юрисдикция и обработчики).
- **Подготовлено:** docker-compose локальная среда, PITR-совместимая конфигурация
  PostgreSQL 17 и процедуры backup/restore. Локальное учение измеряет RTO и
  проверяет целостность копии; RPO и WAL/PITR не доказаны без архива WAL.
  Рабочее хранилище — filesystem; S3-совместимый адаптер не реализован.
- **Условие снятия:** выбранный провайдер и доступы.

## BL-05 — Режим аудитории бота (OPEN-04)

- **Нужно:** открытый `/start` с созданием бюджета для любого пользователя или
  закрытый пилот с allowlist создателей; суммы сервисных квот.
- **Влияет на:** конфигурация запуска, ADR-12, R12.
- **Подготовлено:** обе ветки реализованы конфигурацией
  (`BOT_CREATION_MODE=open|allowlist`), значение по умолчанию — `allowlist`
  для пилота, с понятным сообщением пользователю.
- **Условие снятия:** решение пользователя перед production webhook. **Не блокирует разработку.**

## BL-06 — Объём P2 (банки, форматы, валюты)

- **Нужно:** страна, конкретные банки/форматы выписок, нужна ли мультивалюта и
  какие пары, какие дополнительные сценарии целей.
- **Влияет на:** S17–S20.
- **Подготовлено:** контракты `StatementImportAdapter` и `BankApiAdapter`,
  нормализованная промежуточная модель выписки, правила дедупликации с
  существующими чеками, контракт мультивалюты (курс как точное десятичное,
  дата курса, запрет смены валюты заполненного бюджета).
- **Условие снятия:** выбор пользователя. Выдуманный банковский endpoint
  не реализуется (раздел 10 инструкции).

## BL-07 — Предметные уточнения владельца (SOURCE_ANALYSIS §7)

- **Нужно:** подтверждение валюты RUB, смысл строк «Шанелька» и «Родители/Пенсия»,
  какие категории обязательные, перечень счетов и режимов их охвата.
- **Влияет на:** только данные конкретного бюджета, не архитектуру.
- **Решение:** всё это задаётся пользовательским мастером в приложении
  (OPEN-06), значения не зашиваются в код. **Не блокирует разработку.**
