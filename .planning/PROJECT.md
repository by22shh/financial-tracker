# PROJECT — Финансовый трекер в Telegram

## Цель

Реализовать приложение из комплекта требований версии 0.7 (`docs/`): Telegram-бот
для личных и совместных бюджетов с быстрым вводом (текст/голос/чек), точным
денежным учётом, настраиваемыми повторяющимися периодами, совместным доступом,
аналитикой и периодическими AI-рекомендациями.

## Источники требований (порядок приоритета)

1. `README.md` — состав и версия
2. `docs/TZ.md` — поведение (FR-01…94, AI-01…09, TECH-01…07, QA-01…04, НФТ, хранение)
3. `docs/ARCHITECTURE.md` — ADR-01…17 (технический механизм)
4. `docs/DATA_CONTRACT.md` — инварианты, схема, CMD-01…31
5. `docs/ACCEPTANCE.md` — A01…A230, B1…B10
6. `docs/ARCHITECTURE_REVIEW.md` — AR-01…36, OPEN-01…06
7. `docs/SOURCE_ANALYSIS.md` — структура исходной таблицы, правила миграции
8. `docs/SPEC_REVIEW.md`, `docs/RESEARCH.md` — история замечаний и основания

Правило разрешения противоречий: ТЗ определяет поведение, ADR — механизм,
контракт данных — инварианты, приёмка — проверяемый результат. Более новая
версия отменяет историческое замечание аудита. F01–F06 из SPEC_REVIEW **не входят**
в объём: они остаются предложениями. Исключения раздела 3 ТЗ сохраняются
(нет автоплатежей, распоряжения средствами, инвестиций, налогов, публичной подписки).

## Зафиксированный профиль AI приложения (ADR-17)

| Параметр | Значение |
|---|---|
| Провайдер | OpenAI напрямую |
| Base URL | `https://api.openai.com/v1` |
| Endpoint | `POST /responses` (Responses API) |
| Model ID | `gpt-5.6-luna` |
| `reasoning.effort` | `medium` |
| `service_tier` | `default` |
| Ключ | `OPENAI_API_KEY` из secret manager среды |
| Голос | отдельный ASR → текст → тот же профиль Luna Medium |

Это профиль **разрабатываемого приложения**, а не требование к модели агента-разработчика.
Скрытая подмена модели/effort/провайдера/тарифа запрещена; недоступность API
приводит к повторам, деградации на ручной ввод и явному сообщению.

## Этапы объёма

| Этап | Содержание |
|---|---|
| P0 | Полный первый выпуск (раздел 3 ТЗ, столбец P0) |

| P2 | Импорт банковских форматов, разрешённые банковские API, мультивалюта, доп. сценарии целей |
