# Стартовый промпт для AI-разработчика

Вставь текст ниже в интерфейс AI-агента с доступом к репозиторию financial-tracker, изменению файлов, запуску приложения и тестов. Основная инструкция — [AI_DEVELOPMENT_GUIDE.md](AI_DEVELOPMENT_GUIDE.md).

Промпт задаёт последовательную реализацию P0 → P1 → P2. Если нужен только первый выпуск, замени весь абзац, начинающийся с «Выполняй P0 → P1 → P2», на: «В этой задаче полностью реализуй и проверь P0; P1/P2 пока не выполняй. Не заканчивай на плане или прототипе. При недостающих внешних входах продолжай независимую работу и явно фиксируй блокеры».

```text
Разработай financial-tracker в текущем репозитории до полного выполнения согласованного ТЗ.

Сначала прочитай docs/AI_DEVELOPMENT_GUIDE.md и выполняй его как рабочую инструкцию. Полностью изучи перечисленные там документы, проверь фактическое состояние репозитория и сохрани существующие изменения.

Выполняй P0 → P1 → P2 последовательно. Не заканчивай на плане, прототипе или завершении одного P0. Не добавляй несогласованные идеи из исследования. Для недоопределённых интеграций подготовь контракт и запроси только действительно недостающее решение, продолжая независимую работу.

Сохрани принятые ADR и профиль AI приложения: gpt-5.6-luna, reasoning.effort=medium, прямой OpenAI Responses API, service_tier=default. Для голоса нужен отдельный ASR. Это профиль приложения, а не требование менять модель агента-разработчика.

Создай реестр требований, план вертикальных срезов и связь «требование → реализация → проверка → доказательство». Используй GSD, если доступен; иначе веди эквивалентные артефакты. Сохраняй прогресс и следующий шаг в .planning, чтобы продолжать после смены контекста.

Для каждого среза: реализуй полный пользовательский путь → запусти подходящие проверки → проведи отдельное ревью фактических изменений → исправь замечания → повторно проверь затронутые пути. На границе этапа проведи полную приёмку и проверку взаимодействия модулей. Не ослабляй требования и тесты ради успешного результата.

Действуй автономно в разрешённом объёме, без повторных вопросов «продолжать?». Недостающие ключи, лимиты и разрешения обозначай конкретно. Заглушки, незапущенные тесты и непроверенные внешние интеграции не считай готовыми.

Заверши итоговым аудитом требований и передай код, инструкции запуска, миграции и доказательства проверок. Если остаётся реальный внешний блокер, явно укажи степень готовности и точку продолжения вместо заявления «100% готово». Начинай работу сейчас.
```
