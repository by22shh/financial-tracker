# Расходы в Google Sheets через Telegram

Бот записывает расходы в последний видимый лист вашей таблицы, помогает исправлять
записи и показывает сводки по запросу.

1. Написать «продукты 1250», «вчера доставка 890» или отправить голосовое.
2. AI определит сумму, дату и категорию из последнего листа. Бот сразу прибавит сумму
   в нужную ячейку и ответит: «Записано в …».

Если не хватает суммы или непонятно, для кого расход, бот задаст короткий вопрос.
Следующее сообщение продолжает этот ввод; кнопка «✖️ Отменить ввод» отменяет уточнение.
Несколько однозначных расходов в сообщении записываются вместе.
Последний лист определяется по порядку вкладок слева направо перед каждым новым расходом.
Скрытые и служебные листы не учитываются. Новый крайний справа лист подхватывается
автоматически. Выбора листа в боте нет; после `/start` появляется постоянное меню под полем сообщения.
Если при уточнении сменился лист, бот попросит прислать расход целиком.

## Ежедневное использование

- Под квитанцией — **✏️ Изменить** и **↩️ Отменить**. В пакете из нескольких трат
  сначала выберите нужную. Исправление можно написать или надиктовать: «Сумма 350»,
  «Это кафе», «Дата — вчера». «✖️ Отменить ввод» выходит без изменения записанного расхода.
- После голосового бот показывает, что услышал. Аудиофайл не сохраняется.
- Исправления категорий запоминаются отдельно для каждого пользователя и передаются AI
  при следующих покупках. Явно указанная новая категория важнее запомненной.
- Совпадение суммы, категории и даты за последние 5 минут требует подтверждения
  «Да, это ещё одна трата». Проверка действует в рамках пользователя и текущего листа.
- Кнопки «📊 Сегодня», «🗓 За неделю», «📈 За весь период» или вопросы «Сколько потратил сегодня?» и «Расходы на продукты
  за период» показывают суммы непосредственно из таблицы, включая ручные записи и
  результаты формул. Поддерживаются сегодня, вчера, последние 7 дней (включая сегодня) и весь последний период.
  Неделя ограничена датами рабочего листа; в ответе показан фактический диапазон.
- «📅 Новый период» предлагает создать лист текущего периода по последнему месячному шаблону.
  Создание происходит только по кнопке. Копируются оформление, категории и итоговые
  формулы; дневные ячейки расходов очищаются, E4 и дни обновляются. После создания
  нужно прислать расход заново. Пропущенные месяцы не создаются.

Выбора прошлых листов нет. Исправление доступно для новых квитанций, пока их лист
остаётся последним и его структура не изменилась. Старые кнопки после исправления
не действуют. Каталог категорий редактируется в самой Google-таблице.

## Формат таблицы

Поддерживается исходная матрица: категории в C14:C…, уточнения в E14:E…,
дни в I13:AM13, расходы на пересечении категории и дня. Первая строка,
где B начинается с «Итого», завершает список категорий. Итоговые колонки и
форматирование бот не меняет. Существующее выражение в дневной ячейке сохраняется:
`=(438+741)/2` после траты 250 превращается в `=((438+741)/2)+(25000/100)`.

Год и начало периода берутся из E4, если дата совпадает с началом названия листа
`10.08 - 09.09`. Для других названий или скопированных листов начало задаётся явно
через `SHEET_START_DATES` в настройках Google Apps Script. Бот откажется подгонять
дату расхода под старый лист. Если последняя вкладка не содержит актуальных дат,
используйте кнопку «📅 Новый период» или добавьте новый лист вручную. Автосоздание поддерживает
месячные периоды с первым днём от 1 до 28 и непрерывной матрицей дат. Для других
шаблонов бот просит создать лист вручную. Предыдущие периоды бот не выбирает.
Категории перечитываются перед каждым распознаванием.

По умолчанию валюта — RUB, часовой пояс — Asia/Novosibirsk. Их можно изменить в `.env`.
Это настройки бота: валюта не выводится из формата ячеек и автоматически не конвертируется.

## Подключение

Нужны Python 3.13, `uv`, токен Telegram, OpenAI API key и доступ владельца Google-таблицы.
Токен существующего бота можно использовать повторно. Google Apps Script выполняет
запись от аккаунта владельца; публичной ссылки для чтения недостаточно.

1. Откройте таблицу → Расширения → Apps Script. Вставьте
   [Code.gs](integrations/google_sheets/Code.gs). Добавьте сервис **Google Sheets API v4**
   через «Сервисы +» (или используйте [appsscript.json](integrations/google_sheets/appsscript.json)).
2. В настройках проекта → Свойства скрипта задайте:
   - `SPREADSHEET_ID` — ID из ссылки таблицы;
   - `BRIDGE_SECRET` — случайный секрет длиной от 32 символов;
   - при необходимости `SHEET_START_DATES`, например `{"182481067":"2026-08-10"}`.
3. Разверните как веб-приложение: выполнение от вашего аккаунта, доступ «Все».
   Доступ к операциям защищён `BRIDGE_SECRET`. Скопируйте URL, оканчивающийся `/exec`.
4. Перенесите настройки из [.env.example](.env.example) в локальный `.env`, сохранив
   существующий токен. Укажите URL, тот же секрет и числовые Telegram ID пользователей.
   Пустой список пользователей запрещает запуск. Ключи не нужно отправлять в чат или Git.
5. Настройте AI и транскрипцию. Профиль текста: `gpt-5.6-luna`, effort `medium`.
   Для голоса задан `gpt-4o-mini-transcribe`; его доступность зависит от API-аккаунта.

```bash
uv sync --frozen
uv run fintracker check
uv run fintracker poll
```

`check` проверяет настройки, доступ к последнему листу, его категории и даты. Он не проверяет
качество AI, оплату OpenAI или возможность записи во все ячейки.
Для настоящей проверки записи нужен отдельный тестовый лист.

Docker: `docker compose up -d --build`. Один экземпляр бота, постоянный том `sheetstate`.
PostgreSQL, API и планировщик для новой версии не нужны.

## Хранение и деплой

Расходы хранятся в Google Sheets. Локальный SQLite-файл содержит очередь сообщений,
незавершённые уточнения, квитанции с расходами для исправления, подтверждения
и персональные исправления категорий. Расшифровка голосового сохраняется с квитанцией;
аудио не сохраняется. Сохраняйте том `sheetstate` при обновлении.

Инструкция для рабочего сервера: [deploy/README.md](deploy/README.md).

## Надёжность и проверки

Перед записью бот сохраняет распознанный расход, лист и идентификатор сообщения на диск.
Apps Script сериализует записи бота и в одном атомарном `batchUpdate` изменяет ячейки
и добавляет квитанцию в скрытый лист `_telegram_expenses`. Повтор после потери ответа
возвращает ту же квитанцию, даже если появился новый лист. Если новый лист появился
до первой записи, запрос отклоняется с просьбой повторить расход. **Не удаляйте этот служебный лист**: он предотвращает дубли.
Финансовые данные не передаются в лог. Содержимое обработанных сообщений удаляется
из локальной очереди; технические идентификаторы остаются.

Блокировка Apps Script координирует только этот скрипт. Ручное редактирование той же
ячейки одновременно с записью бота может конфликтовать. При недоступности таблицы
запрос сохраняется и повторяется; очередь сохраняет порядок сообщений. Telegram может
повторно доставить ответ при потере подтверждения отправки, но сумма повторно не добавится.
Редактирование самого Telegram-сообщения не изменяет проведённый расход — используйте
кнопку под квитанцией. Исправление и отмена применяют разницу сумм в том же атомарном
запросе, что и обновление версии квитанции. Остальные расходы ячейки сохраняются.
Ручное изменение суммы после записи не всегда можно распознать: отрицательный результат
отмены блокируется, но при существенной ручной переработке листа исправляйте его напрямую.

При обновлении сначала опубликуйте актуальный `Code.gs` как новую версию существующего
развёртывания Apps Script (URL тот же), затем обновляйте контейнер бота. Старые технические
квитанции совместимы с повторами, но не содержат данных для кнопок исправления.

```bash
make check
```

Проверки используют управляемые ответы AI/Telegram/Google; они не заменяют живую проверку
с вашей таблицей и аккаунтами. Node.js нужен только для тестов Google Apps Script.

Контракты интеграции: [Google batchUpdate](https://developers.google.com/workspace/sheets/api/guides/batchupdate),
[Google LockService](https://developers.google.com/apps-script/reference/lock/lock-service),
[развёртывание Apps Script](https://developers.google.com/apps-script/guides/web),
[OpenAI transcription](https://developers.openai.com/api/docs/guides/speech-to-text).
